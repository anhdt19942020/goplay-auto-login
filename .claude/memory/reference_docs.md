## Documentation Files

**Project Architecture**
- Location: `@docs/architecture.md`
- Contains: System overview, components, data flow
- Update when: Major structural changes

**API Standards**
- Location: `@docs/api-standards.md`
- Contains: Endpoint patterns, response formats, error codes
- Update when: Adding new APIs or changing response structure

**Database Schema**
- Location: `@docs/database-schema.md`
- Contains: Mongoose schemas, relationships, indexes
- Update when: Modifying MongoDB collections

## Code-Based Documentation

- Inline comments: Explain *why*, not what
- JSDoc comments: Document function signatures
- Examples: Include in API endpoints documentation
- Error messages: Should guide users to fix

## Generated Documentation

- API docs: Generated by `/doc` command (see Claude Code slash commands)
- Coverage reports: Generated by test suite
- Performance profiles: Run before/after optimizations

## How to Apply

When changing API: update `docs/api-standards.md`
When creating table: update `docs/database-schema.md`
When refactoring: update `docs/architecture.md`
When adding feature: include inline documentation
